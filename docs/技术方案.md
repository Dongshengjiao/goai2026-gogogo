# GOAI 2026 具身未来赛道 · 技术方案

## 一、项目概述

### 1.1 项目信息

| 项目 | 内容 |
|---|---|
| 赛道 | 具身未来 Embodied Future |
| 赛题 | 赛题一：通用双臂协作操作能力测试 |

### 1.2 项目简介

本项目面向 GOAI 2026 具身未来赛道赛题一，构建了一套基于 **RoboDojo 基准** 和 **XPolicyLab 策略框架** 的视觉-语言-动作（VLA）策略评测系统。系统以 WebSocket 通信协议对接官方 X-Eval 仿真评测平台，实现了从多视角视觉观测输入、自然语言指令理解到双臂末端位姿/关节角动作输出的完整感知-决策-执行闭环。

项目采用模块化设计，支持任意 VLA 模型的即插即用接入，并提供了从环境搭建、冒烟测试、远程部署到评测提交的全链路工程化工具链。

### 1.3 问题定义

RoboDojo 基准包含 12 项双臂协作操作任务，涵盖刚体操作（叠碗、推物、装箱）、柔性物体操作（折衣服）、液体操控（倒液体）、工具使用（做烤面包）等多种场景。每项任务有标准配置和随机化配置共 24 个评测配置，对策略的泛化能力、精确控制和长时序规划提出挑战。

核心挑战包括：
- **Sim-to-Real 迁移**：仿真训练的策略需具备在真实场景中的泛化能力
- **多模态感知融合**：多视角视觉观测 + 自然语言指令的联合理解
- **双臂协同控制**：两臂的协调操作与碰撞避免
- **长时序任务规划**：多步骤复杂操作的序列决策
- **随机化泛化**：在物体位姿、光照等扰动下的鲁棒性

### 2.2 通信协议

Policy Server 与 X-Eval 评测平台通过 WebSocket 通信，使用 MessagePack 二进制序列化：

```
评测平台 ──WebSocket──→ Policy Server

请求消息 (MessagePack):
{
    "cmd": "update_obs",      # 命令：update_obs / get_action / reset
    "request_id": "<uuid>",   # 请求 ID
    "obs": {                  # 观测数据
        "vision": {           # 多视角视觉
            "front": {"color": <HxWxC array>},
            "wrist_left": {"color": <HxWxC array>},
            "wrist_right": {"color": <HxWxC array>}
        },
        "state": {            # 机器人本体状态
            "ee_pose": [...],
            "joint_pos": [...]
        },
        "instruction": "Stack the three bowls together."
    }
}

响应消息 (MessagePack):
{
    "request_id": "<uuid>",
    "actions": [              # 动作 chunk（chunk_size 条）
        {
            "ee_pose": [x, y, z, qx, qy, qz, qw],
            "gripper": 0.0
        },
        ...
    ]
}
```

### 2.3 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 通信协议 | WebSocket + MessagePack | XPolicyLab 标准，低延迟二进制传输 |
| 动作类型 | ee（末端位姿） | 末端位姿更通用，便于 sim-to-real 迁移 |
| 动作 chunk | 10 步 | 平衡推理频率与控制平滑度 |
| 时间聚合 | 开启 | 减少 chunk 边界处的动作跳变 |
| 降级策略 | demo_policy（零动作） | 确保 torch 缺失时链路仍可通 |
| 部署方式 | 独立 Policy Server + 公网暴露 | 评测平台主动连接，无需反向穿透 |

## 三、核心模块设计

### 3.1 Model 策略适配器（model.py）

Model 类是系统的核心，实现 XPolicyLab 的标准 Model 契约接口：

```python
class Model:
    def __init__(self, model_cfg: dict) -> None:
        """从 deploy.yml 加载配置和模型权重"""

    def update_obs(self, obs: dict) -> None:
        """接收单条观测（含多视角相机图像、本体状态、语言指令）"""

    def update_obs_batch(self, obs_list: list) -> None:
        """批量接收观测（多环境并行评测）"""

    def get_action(self) -> list[dict]:
        """生成动作 chunk 并返回（chunk_size 条动作）"""

    def get_action_batch(self, env_idx_list: list) -> list[list[dict]]:
        """批量返回动作（多环境并行评测）"""

    def reset(self) -> None:
        """episode 之间清除状态"""
```

**双模式运行机制**：
- **真实模式**：检测到 torch + checkpoint 权重时，加载 VLA 模型进行推理
- **Demo 模式**：torch 不可用或权重缺失时，返回零动作，保证冒烟测试链路可通

**观测处理**：
- 滑动窗口维护最近 16 条观测历史
- 支持多视角视觉输入（前视、左腕、右腕相机）
- 自动提取图像数组，传递给 VLA 模型的视觉编码器

**动作生成**：
- ee 模式：返回 `[x, y, z, qx, qy, qz, qw, gripper]` 末端位姿
- joint 模式：返回 `[j1, ..., j7, gripper]` 关节角
- chunk_size=10，每次推理生成 10 步动作，配合时间聚合减少跳变

### 3.2 模型接入方案

项目支持两种模型接入路径：

**路径一：自定义 VLA 模型接入**

在 `model.py` 的 `_load_model()` 和 `get_action()` 中实现：

```python
def _load_model(self):
    from transformers import AutoModelForVision2Seq, AutoProcessor
    self._model = AutoModelForVision2Seq.from_pretrained(
        str(self.ckpt_path), torch_dtype=torch.bfloat16
    ).to(self.device)
    self._processor = AutoProcessor.from_pretrained(str(self.ckpt_path))

def get_action(self):
    obs = self._obs_history[-1]
    images = [v["color"] for v in obs.get("vision", {}).values()]
    inputs = self._processor(images=images, text=obs.get("instruction", ""))
    outputs = self._model.generate(**inputs)
    return self._decode_actions(outputs)
```

**路径二：XPolicyLab 已集成策略**

XPolicyLab 已集成 41 个策略（ACT、π0、MolmoAct2 等），可将 `policy_adapter/` 替换为对应策略目录直接使用。

## 四、评测任务

### 4.1 任务概览

RoboDojo 基准的 12 项任务覆盖了双臂操作的典型场景：

| 任务 | 指令 | 难度特点 |
|---|---|---|
| stack_bowls | 三个碗叠放 | 精确位姿对齐，重力稳定 |
| push_T | 推 T 形物体到目标位 | 非抓取操作，接触力控制 |
| pack_objects_into_box | 物体装箱 | 多物体操作，空间规划 |
| fold_clothes | 折衣服 | 柔性物体，高度非确定性 |
| hang_mugs | 挂杯子 | 精确孔对齐，双臂协同 |
| sweep_blocks | 扫积木 | 非抓取操作，区域清扫 |
| pour_liquid_into_cup | 倒液体 | 流体物理仿真，高度动态 |
| make_toast | 做烤面包 | 工具使用，多步骤 |
| arrange_largest_number | 排列最大数字 | 认知 + 操作，数字识别 |
| sort_nesting_dolls_by_size | 套娃按大小排序 | 大小比较，嵌套操作 |
| store_laptop_and_headphones | 收纳笔记本和耳机 | 多物体，脆弱物体处理 |
| stack_blocks | 叠积木 | 精确堆叠，重力稳定 |

### 4.2 评分标准

每项任务采用三级评分：
- **0 分**：任务未完成
- **15 分**：部分完成（如任意两碗叠放成功）
- **100 分**：完全完成（全部目标达成 + 机器人回归原位 + 夹爪打开）

每项任务有标准配置和 `_random` 随机化配置，共 24 个评测，总分 2400。

### 4.3 评测流程

```
1. 评测平台启动仿真环境 (Isaac Sim 5.1)
         │
         ▼
2. 通过 WebSocket 连接 Policy Server
         │
         ▼
3. 发送 reset 指令 ──→ Model.reset()
         │
         ▼
4. 循环 (24 配置 × N episodes):
   │
   ├─ 4a. 发送 update_obs (视觉+状态+指令)
   │       └─→ Model.update_obs(obs)
   │
   ├─ 4b. 发送 get_action
   │       └─→ Model.get_action() → 返回 10 步动作 chunk
   │
   ├─ 4c. 仿真器执行动作，更新环境状态
   │
   └─ 4d. 重复 4a-4c 直到 episode 结束
         │
         ▼
5. 评分计算，写入 eval_result/
         │
         ▼
6. 发送评测结果邮件
```

## 六、鲁棒性设计

### 6.1 降级机制

```python
try:
    import torch
    _HAS_TORCH = True
except Exception:
    torch = None
    _HAS_TORCH = False
```

- torch 不可用 → demo 模式（零动作），冒烟测试仍可验证链路
- checkpoint 不存在 → 降级为 demo 模式，打印警告日志
- 模型加载失败 → 捕获异常，降级为 demo 模式，不影响服务启动

### 6.2 连接可靠性

Policy Server 配置了完整的连接保活和超时机制：

```yaml
# 超时与重试
request_timeout_s: 120.0          # 单次请求超时
max_connect_attempts: 180         # 最大连接重试次数
connect_retry_delay_s: 5.0        # 重试间隔
max_connect_seconds: 900.0        # 最大连接等待时长
connect_timeout_s: 30.0           # 连接建立超时
handshake_timeout_s: 60.0         # WebSocket 握手超时
ws_ping_interval_s: 20.0          # 心跳间隔
ws_ping_timeout_s: 20.0           # 心跳超时
close_timeout_s: 10.0             # 关闭超时
```

### 6.3 独立运行模式

当 XPolicyLab 框架不存在时，Policy Server 可独立运行，内置 WebSocket + MessagePack 通信，直接调用 Model 接口，无需依赖 XPolicyLab：

```python
# setup_eval_policy_server.sh 中的独立模式
python -c "
import websockets, asyncio, msgpack, yaml
from policy_adapter.model import Model

model = Model(cfg)

async def handle(ws):
    while True:
        data = await ws.recv()
        req = msgpack.unpackb(data, raw=False)
        # 处理 update_obs / get_action / reset 命令
        ...
"
```

### 9.2 技术风险评估

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| VLA 模型推理延迟 | 评测超时 | 使用 bf16 精度 + GPU 加速，chunk 减少推理频率 |

| GPU 显存不足 | 无法加载大模型 | 支持 16GB+ VRAM，bf16 精度优化 |
| 网络不稳定 | 评测中断 | 心跳保活 + 重连机制 |

## 十一、总结

本项目构建了一套面向 GOAI 2026 具身未来赛道的完整 VLA 策略评测系统，核心价值在于：

1. **完整的感知-决策-执行闭环**：从多视角视觉观测到双臂动作输出的全链路实现

4. **鲁棒的系统设计**：降级机制、连接保活、独立运行模式
5. **完整的开源计划**：代码 + 文档 + 工具链全量开源，支持社区复现和扩展

项目已验证端到端链路可通，具备接入真实 VLA 模型的能力，为后续模型微调和评测优化奠定了坚实的工程基础。
